## Residual image advisories at the published main release

The [tracked review policy](CONTAINER_ADVISORY_TRIAGE.json) retains every high/critical package/CVE row with its version, path, reason and primary Debian tracker reference. It expires **6 November 2026**. The release gate fails new findings, changed package versions/paths, newly available distribution fixes, changed security build/runtime inputs, missing reports and expired reviews. It does not automatically accept the latest scan output.

Current pinned images contain 44 OS package/CVE rows (eight distinct CVEs) each in the dashboard and runner; the worker and Requests image each contain 112 rows (76 distinct CVEs). Worker counts include two critical scanner candidates: `libxml2` and `linux-libc-dev`. Kernel headers are not a running kernel, and the affected `systemd-homed` service is absent. These are distinguished from actual vulnerable native libraries, rather than combined into a proven-exploit count.

Native XML parsing libraries remain installed with compiler/CMake tooling. For example, Debian still records the Trixie versions as vulnerable for [libxml2 CVE-2026-6653](https://security-tracker.debian.org/tracker/CVE-2026-6653), [libxml2 CVE-2026-86138](https://security-tracker.debian.org/tracker/CVE-2026-86138) and [Expat CVE-2026-76957](https://security-tracker.debian.org/tracker/CVE-2026-76957). Their reachability is **not declared absent**. Dedicated-worker isolation, target UID 65534, dropped target capabilities, no external network, readonly containers, no host bind mounts and bounded resources constrain impact; these controls are not proof against container escape or a substitute for host patching. Sensitive/unfamiliar workloads require separately qualified dedicated worker and deployment controls. A shared public worker is outside this release scope.

Mount/cgroup privilege paths lack the required runtime capabilities. Curl connection paths are constrained by offline execution. Perl/archive and terminal-library process risks remain bounded to disposable target execution. Individual records retain these conditions; changed capabilities, services, network access or entrypoints require renewed review.

The dashboard's two `tree-kill` findings belong to one exact, deliberately vulnerable benchmark overlay, not an installed runtime dependency. No broad benchmark or npm exclusion is applied. Pip's original `bom.cdx.json` mixes build-time provenance and bundled library pins. A metadata-only audit initially missed bundled urllib3 2.7.0 and msgpack 1.1.2; direct module inspection identified the gap. Hash-verified wheel overrides now update those actual bundled modules to urllib3 2.8.0 and msgpack 1.2.1. The audit includes `vendor.txt` components without dist-info and fails missing modules. The original BOM remains historical and is excluded from current component inference; actual bundled components are audited separately. Two specific setuptools advisories are reviewed as inapplicable to pip's pkg_resources-only copy: the affected [PackageIndex](https://github.com/pypa/setuptools/security/advisories/GHSA-5rjg-fvgr-3xxf) and [FileList/sdist](https://github.com/pypa/setuptools/security/advisories/GHSA-h35f-9h28-mq5c) modules are absent. Both raw advisory results are retained; any other advisory or a full setuptools copy still fails the gate. Original scan observations remain in the historical assessment.

## Subsequent Requests worker hardening — local follow-up, 7 October 2026

The Requests reference-fix worker now builds directly from the pinned Python base rather than the general compiler worker. It retains the trusted worker supervisor, target UID 65534, dropped target capabilities, offline execution and hash-locked Bandit/Requests dependencies. Its preparation no longer builds the general worker. Runtime pip, setuptools and wheel are uninstalled.

Actual runtime checks confirm that LLVM/Clang, CMake, Make, Node/npm, native libxml2/libexpat/libcurl and development headers are absent. CPython's separate bundled Expat remains present as version 2.8.5; it is not confused with removal of the OS libexpat1 package. Debian's [UTF-16 advisory](https://security-tracker.debian.org/tracker/CVE-2026-93990) identifies 2.8.5 as the upstream fixed release for the latest of the four Expat findings in the previous OS scan. This is version/applicability verification, not a complete audit of every CPython native component.

The same pinned scanner/database reports 44 high and zero critical findings in the smaller Requests image, down from 112 high/critical rows. The 68 removed rows disappear because their packages are absent, not because scanner findings were suppressed. The remaining 44 rows retain their previous dated reviews; the policy removes only obsolete Requests entries and binds the new Dockerfile and tools lock. The Python package audit finds 12 distributions with no applicable advisories, and no pkg_resources partial-copy exception is needed in this image.

The focused Requests/preparation/dashboard/export/inventory/advisory checks passed: 21 tests with actual Docker and no skips. After the evidence-writer fixes described below, the complete combined follow-up suite passed: **257 Python tests with Docker enabled and no skips in 523.69 seconds; 3 frontend tests passed**. The rebuilt production image passed authenticated/read-only checks, including host rejection, and its 20 Python distributions had no applicable advisories. Bandit reported no medium/high findings, the four-image advisory gate passed, and wheel inspection confirmed the new lock and controller fixes were packaged. Rechecking 1,264 original file hashes and all 24 nested repository heads found no changes. This follow-up remains local and uncommitted; published main and its CI evidence above describe the previous release. Frontend source and layout have not changed.

The first combined follow-up run exposed a pre-existing Windows evidence-writer race: 254 passed and one failed because an unlocked initializer write collided with another writer's byte-range lock. Stress testing reproduced it. Locks now acquire the OS lock on the empty file without that write; Microsoft documents [locking past the end of a file](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170). Evidence index connections also close explicitly after transaction completion: Python's [SQLite transaction context manager](https://docs.python.org/3.11/library/sqlite3.html#how-to-use-the-connection-context-manager) does not close connections. Two regression tests cover empty-lock contention and closed index handles. One hundred four-writer Windows rounds and twenty Linux production-image rounds preserved signature verification and allowed immediate cleanup. Execution budgets, trust-anchor checks and worker isolation remain unchanged.

The general C/C++ compiler worker still contains required native libraries. Debian currently lists Trixie's [libxml2 CVE-2026-6653](https://security-tracker.debian.org/tracker/CVE-2026-6653) and [CVE-2026-86138](https://security-tracker.debian.org/tracker/CVE-2026-86138) versions as vulnerable, with fixes in newer unstable/testing packages. Replacing ABI-incompatible libraries, removing required compiler dependencies, or suppressing advisories is not an accepted remediation. Further compiler-worker hardening and qualification remain necessary; the overall native OS work is not complete.
