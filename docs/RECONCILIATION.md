# Local reconciliation — 7 October 2026

The integration uses GitHub main as its controller foundation and preserves the
latest demo interface, local verification, cloud tooling and upstream preparation
inputs. Source worktrees remain separate and unchanged. No commit or publication
is part of this stage.

## What was combined

- Continuous Three.js animation and the latest landing-page links and metrics,
  with reduced-motion/static fallbacks and main's deployment protections.
- Supplied-patch demonstrations for three languages and pinned Requests redirect
  logic; actual project stages, labeled outcomes and signed evidence export.
- Evidence-bound cloud accounting, Windows Azure CLI handling, shutdown guard
  acknowledgement, bounded transport retries and worker/model readiness tools.
- All 24 upstream recipes, audit definitions, captured overlays, pinned source
  mappings, license records and observed target adaptations.
- Main's authentication, CSRF, security headers, input limits, independent audit
  boundary, signed qualification requirement and resumable budget accounting.

The campaign API accepts an optional monotonic deadline. It cannot extend the
campaign allowance or erase consumption on resume. It preserves the audit reserve.
Cloud execution still requires a fresh validated ledger and an acknowledged guard.
No Azure resources are started by this integration or its local checks.

## Preparation boundary

`scripts/reconstruct_targets.py` reads pinned Git objects and writes separate
ignored `prepared/` snapshots. Source caches are never reset or cleaned. Existing
output is refused, dry-run writes nothing, and the receipt says qualification was
not run. Captured current overlays take precedence over historical embedded
harnesses; disagreements are reported as blockers. Only obsolete placeholder
harnesses are omitted from disposable snapshots.

The original sources retain their binary fixtures and assets. Main's existing
UTF-8, size, file-count and private-key intake restrictions remain in force.
Unsupported fixtures, links, oversized sources and Windows path failures are
explicit blockers rather than evidence of a passing vulnerability check.

The local preparation review produced **5 prepared snapshots and 19 blocked
cases**. This replaces the older 24/24 structural count, which used larger intake
limits and target checkouts with many assets removed. A prepared snapshot is not
an executable qualification or an independent audit.

The case-by-case explanations are in `reconciliation-inventory.json`. Runtime
qualification, dependencies on dedicated workers and the 216-attempt campaign
remain outside this local stage. No successful qualification records are generated.

## Security claim boundary

Local checks exercise authentication, throttling, CSRF, host restrictions, security
headers, signed evidence and worker isolation. Demonstrations address selected
access-control, injection and credential-exposure risks. This is partial coverage,
not a complete assessment of the [OWASP Top 10:2025](https://top10.owasp.org/2025/en/).
The preview is a localhost development instance; production requires explicit
production mode, authentication secrets and HTTPS deployment configuration.

Browser review confirmed the continuous homepage, a 390-pixel small-screen fallback
without horizontal overflow, Python repair, JavaScript discovery, C++ repair,
Requests reference-fix results, backend stage updates and terminal cancellation
removal. Read-only review exposed no execution actions. Two downloaded evidence
bundles independently verified against the local trusted public key. Requests
reference fix passed four checks and caught its one qualified unsafe mutation;
the incomplete repair was rejected. No browser console errors were observed.

Running preparation with release-exported recipes reproduced the same 24-case
result: five prepared and nineteen blocked. Per-case limitations are recorded in
the inventory; no qualification success was manufactured.

A browser-discovered intermediate-width overflow was corrected by matching the
atmosphere margin to the 651–900 pixel layout. The original continuous animation
and small-screen fallback remain intact. Frontend tests, asset build, wheel and
image checks passed again after this CSS correction; browser document width now
matches the available viewport width.
